# 로컬 수집 준비 범위

단독 기준은 저장소 루트의 `SmartBIS 운영 수집 설계 GPS 없음 최종 기준.md`다.

- 프로필: `local-collection` 하나만 사용한다. 환경 파일은 git 무시 대상인 `.tmp/local-collection.env`다.
- `tools/local_collection_admin.py`가 이 파일만 읽어 검증한다. 최초 생성 때만 기존 로컬 복사본 설정의 필요한 키를 가져온다. 운영 `.env`는 읽지 않는다.
- 관리자 도구는 루프백 주소·지정 복사본 DB·로컬 Podman 연결을 먼저 검증한다. 비밀번호 입력 대기와 임의 주소 재시도를 하지 않는다.
- `schema.sql`은 Flyway 마이그레이션이 아니다. 지정 로컬 DB를 SQL 내부에서도 검증하며 V020이나 정책 테이블을 만들지 않는다.
- 기존 위치·도착 열은 그대로 재사용한다. 추가 열은 예전 행에 허위 시각·호출 ID를 채우지 않으며, 새 로컬 수집에서 실제 호출 메타데이터를 채운다.
- 계획의 이전 행은 세대 키와 비활성 사유·시각으로 보존한다. 새 활성 세대만 수집기가 SELECT한다.
- 위치 요청마다 호출 ID와 실제 요청·응답 시각, lane을 저장한다. 도착은 방문 최종 결과를 먼저 저장하므로 기하 정보가 바뀌어도 응답 이력이 사라지지 않는다.
- 정상 종료는 열린 정지 구간을 만들고 다음 시작에서 닫는다. 미완료 실행이 남으면 마지막 heartbeat부터 재시작까지를 `기타`로 기록한다. 계획된 재부팅 구간이 이미 있으면 그 사유를 보존한다.
- 종료 장치는 각 HTTP 시도 직전에 검사한다. 종료 전에 시작한 진행 중 HTTP의 응답은 종료 시각 뒤에 끝날 수 있으나 새 시도·재시도는 시작하지 않는다.
- 이 준비 도구와 재부팅 검증 도구는 수집 프로세스를 기동하지 않는다. 실제 수집은 G6~G8 확인과 별도 사용자 승인 후에만 한다.

위치 `observed_at`과 도착 `eta_queried_at`/`estimated_arrival_at`, 대상 `next_node_id`는 기존 열을 재사용한다. 추가된 메타데이터 열과 정지 구간은 로컬 DB 정보 스키마 검증 로그에서 확인한다.
