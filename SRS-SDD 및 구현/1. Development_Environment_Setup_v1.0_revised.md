# Development Environment Setup v1.1

## 1. 목적

SmartBIS는 차량용 Android 클라이언트와 서버 사이의 통신 시스템이다. 외부 Tomcat, 브라우저 관리자 화면, /sht_webapp/는 사용하지 않는다.

외부 진입점은 Nginx HTTPS 8443:443 하나이며, Spring Boot는 내장 WAS로 컨테이너에서 실행한다.

## 2. 최종 구성

```text
Android Client
  │ HTTPS 8443
  ▼
Nginx 443
  │ internal HTTP
  ▼
Spring Boot 8080
  ├── PostgreSQL 15
  ├── Node watcher
  ├── TAGO collector
  └── Disaster collector
```

외부에 공개하는 포트는 8443 하나다. PostgreSQL 5432와 Spring Boot 8080은 Compose 네트워크에서만 접근한다.

## 3. 외부 API 환경변수

```properties
TAGO_BASE_URL=https://apis.data.go.kr
TAGO_SERVICE_KEY=
TAGO_CITY_CODE=
TAGO_POLL_INTERVAL_SECONDS=30
DISASTER_API_URL=
DISASTER_API_KEY=
DISASTER_POLL_INTERVAL_SECONDS=30
```

TAGO 서비스키는 소스·로그·Android APK에 저장하지 않는다. 대화에 노출된 키는 운영 전에 폐기하고 재발급한다.

## 4. TAGO 수집 구조

TAGO는 차량번호 직접 검색 API가 아니라 cityCode + routeId로 노선별 버스 위치를 조회한다. 응답의 vehicleno를 관리 DB 차량번호와 대조하여 차량을 찾는다.

```text
차량번호
 → 등록된 cityCode·routeId 조회
 → TAGO 노선별 버스 위치 호출
 → 응답 vehicleno 대조
 → gpslati·gpslong 확인
 → 다음 정류소 좌표와 거리 계산
```

TAGO API 호출은 서버에서만 수행한다.

## 5. Spring Boot

```properties
server.port=8080
server.servlet.context-path=/api
content.root=${CONTENT_ROOT:/app/content-store}
```

Nginx는 context path를 중복시키지 않도록 다음을 기준으로 한다.

```nginx
location /api/ {
    proxy_pass http://egov-backend:8080;
    proxy_buffering off;
    proxy_request_buffering off;
    proxy_read_timeout 300s;
}
```

## 6. 데이터 처리

```text
TAGO 정기 수집
 → regions, bus_stops, bus_routes, bus_route_stops 저장

실시간 위치 수집
 → bus_positions 저장
 → 차량번호·노선·정류소 매칭
 → 100m 판정
 → Android 표출 큐 생성

재난문자 수집
 → disaster_messages 저장
 → 활성 상태 판정
 → 표출 우선순위 반영
```

TAGO 장애 시 마지막 정상 데이터와 수집시각을 보존한다.

## 7. Android

Android는 https://10.0.2.2:8443만 사용한다. Android GPS는 사용하지 않는다. 서버가 TAGO GPS와 정류소 좌표로 계산한 결과만 받는다.

```text
minSdk 30
Room 캐시
OkHttp 또는 Retrofit
ExoPlayer
사설 Root CA
임시 파일 후 원자적 rename
```
