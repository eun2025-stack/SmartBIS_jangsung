# SmartBIS UI 협의사항 및 구현 경계

## 확정 사항

- 대시보드: A안 좌측 메뉴형. 선택한 메뉴의 상세 화면만 표시한다.
- 내부망에서 승인된 콘텐츠가 수신되므로 외부망에서 별도 신청·승인하지 않는다. 메뉴명은 가칭 '데이터 관리'로 변경한다.
- 데이터 관리: 현재 게시 기간에 해당하는 콘텐츠를 상태별로 조회하고, 콘텐츠별 중지·재개·게시 제외·복구를 제공한다.
- 게시 제외는 논리 삭제다. DB의 콘텐츠 원본, 미디어 파일, 수신/검증 이력을 보존하며 상태 변경으로 복구할 수 있다.
- 업무 종류는 공지, 행사, 재난정보, 동영상이다. 업무 종류와 화면 형식을 혼동하지 않는다.
- 화면 형식: 텍스트+포스터, 텍스트 전용, 여러 이미지 카드뉴스, 단일 이미지, 재난정보, 동영상.
- 카드뉴스와 동영상은 전체 재생 종료 후 다음 콘텐츠로 전환한다.
- JSON 전달 구조를 결정한 후 contents 테이블 및 수신 검증기를 변경한다.
- 재난정보 반복 정책은 변경안 결정 후 반영한다.

## 이번 구현

- 실제 대시보드 `static/dashboard/index.html`에 ‘데이터 관리’ 메뉴와 현재 게시 기간의 홍보 콘텐츠 목록·검색·상세를 연결했다.
- `/api/v1/admin/contents` 관리 API는 `ACTIVE`, `PAUSED`, `REMOVED`, `ALL` 상태 필터를 제공한다. 기간이 유효한 홍보 콘텐츠를 기준으로 하며 차량의 실제 재생 상태를 뜻하지 않는다.
- 재난정보는 `disaster_messages`에 별도 저장되어 홍보 콘텐츠 관리 목록에는 포함하지 않는다. 재난정보를 포함한 통합 현황 화면은 별도 작업이다.
- `content_publication_controls`로 기본(게시 중), 중지, 게시 제외 상태를 분리 저장한다. Node watcher의 콘텐츠 UPSERT가 운영 상태를 덮어쓰지 않는다.
- `/api/v1/admin/contents?status=ACTIVE|PAUSED|REMOVED|ALL`은 현재 게시 기간에 해당하는 항목을 상태별 조회한다.
- `PUT /api/v1/admin/contents/{contentId}/publication-state`는 중지·재개·게시 제외를 저장한다. 재개/복구는 override 행을 제거해 기본 게시 상태로 되돌린다.
- 일반 콘텐츠 목록 API와 차량의 다음 표출 선택 API 모두 중지·게시 제외 항목을 제외한다. 표출 중인 동영상/카드는 현재 재생을 마친 뒤 다음 콘텐츠 요청 시 변경 상태가 반영된다.
- 미디어 파일 삭제는 하지 않는다. 이미 클라이언트에 내려받은 파일은 다음 동기화 전까지 기기 캐시에 남을 수 있다.
- V005 마이그레이션을 적용하고 `BUILD SUCCESS` 확인 후 백엔드 이미지를 빌드·재생성했다. 백엔드 재생성 뒤 Nginx가 이전 컨테이너 주소를 사용해 502가 발생했으나 Nginx 재시작 후 관리 API 응답을 확인했다.
- 관리 목록 API에서 현재 유효한 콘텐츠 7건을 조회했고, 대시보드 메뉴·상태 필터·버튼을 브라우저에서 확인했다. 브라우저 콘솔 오류는 없었다.
- 사용자가 시험 항목으로 중지→재개와 게시 제외→재개를 수행해 정상 동작을 확인했다. 게시 제외는 파일 및 콘텐츠 행을 보존하고 상태만 바꾼다.
- 관리자 인증은 Spring Security 폼 로그인과 `ADMIN` 권한으로 적용한다. 단일 관리자 계정은 `.env` 환경변수로 공급하고 BCrypt로 검증한다.
- `/api/dashboard/**`와 `/api/v1/admin/**`은 로그인 및 관리자 권한이 필요하다. Android 공개 API는 인증 대상에서 제외하고, 관리 변경은 CSRF 토큰으로 보호한다.
- 콘텐츠·표출 정책 변경자는 요청 본문이 아닌 로그인 계정으로 기록한다. 세션은 30분 유휴 만료이며 쿠키는 Secure, HttpOnly, SameSite=Strict다.
- `configure-dashboard-admin.sh`에서 계정·비밀번호를 대화식 입력해 `.env`에 저장한다. 비밀번호 확인이 일치하기 전에는 파일을 변경하지 않으며 입력 문자열은 터미널에 표시하지 않는다. `.env`는 Git 제외 대상이다.
- 현재는 단일 계정이며 `.env`와 컨테이너 환경에는 비밀번호가 평문으로 전달된다. 실제 운영 전에는 Podman secret 등으로 이전해야 한다.
- 표출 정책 화면에 새 카드뉴스와 기존 CARD 의미가 다름을 명시했다. 실제 정책 값은 바꾸지 않았다.
- JSON 계약과 `contents` 테이블 컬럼, Android 앱 코드는 변경하지 않았다. 게시 상태용 별도 테이블 `content_publication_controls`만 추가했다.

## Android 디자인 기준

참고 원본: UI Prototype/Claud/장성 자연친화형_v3.0.html. 약 70% 협의된 원본은 변경하지 않는다.

- 1920×1080 화면, 큰 글씨, 자연친화형 산 배경, 녹색·테라코타 색상을 디자인 근거로 삼는다.
- 텍스트+포스터는 이번 협의의 명시적 예외로 좌측 포스터/우측 텍스트 배치한다. 독립적인 여러 콘텐츠로 화면을 분할하지 않는다.
- 참조 HTML의 포스터·이미지 cover 설정은 가장자리를 자른다. 안내 포스터는 내용 유실을 피하는 contain이 권장되지만 최종 화면으로 확인해야 한다.
- 참조 HTML에는 노란색 변수·버스 창문·옵션 버튼이 남아 있다. 이전 노란색 배제 요구와 충돌하므로 색상 교체가 필요하다.
- 동영상 원본은 loop가 설정되어 있다. 운영본은 loop를 제거하고 ended 이벤트로 전환해야 한다.
- 제목 오버레이가 원본에서 130px이다. 실제 영상 가림 정도를 확인하고 제목만 적절한 크기·반투명 배경으로 조정한다.
- 카드뉴스 다중 이미지 재생은 참고 HTML에 아직 없다. 별도 구현이 필요하다.
- 참고 HTML의 Google Fonts 의존성은 오프라인 Android 운영에 맞춰 로컬 폰트로 대체해야 한다.
- BI/CI·캐릭터 오버레이 위치 3안은 원본의 비교 기능이다. 최종 선택은 아직 확정으로 간주하지 않는다.

## 다음 결정 사항

1. 중지/게시 제외 변경이 이미 캐시된 Android 기기에 즉시 전달되어야 하는지, 다음 동기화부터면 충분한지 운영 SLA를 정한다.
2. 카드뉴스 전달 방식: 이미지 배열+장당 시간인지 GIF 파일인지. GIF 무한 반복만으로는 전체 재생 종료를 판정할 수 없다. 재생 횟수나 총 시간도 정의해야 한다.
3. 업무 종류와 화면 형식을 분리하는 JSON 필드, 다중 첨부파일 목록, 기존 CARD 데이터 호환 규칙.
4. 게시 제한 날짜와 실제 행사 일시는 다른 정보다. 표출 문구의 행사 일정은 별도 데이터로 전달하거나 제공 텍스트를 사용한다.
5. 재난 반복 정책과 긴급 개입 규칙.

## 검증 상태

게시상태 관리 기능은 JavaScript 문법 검사, 백엔드 패키징, 관리 API 조회, 실제 대시보드 브라우저 표시 및 콘솔, 사용자의 중지/재개·게시 제외/복구 동작까지 확인했다. 관리자 인증은 계정 저장, 인증 포함 `BUILD SUCCESS`, 컨테이너 반영을 완료했다. 사용자는 대시보드 로그인이 성공했다고 확인했다. 비인증 관리자 API의 `401` 응답과 Android 공개 API 접근은 컨테이너에서 확인했다. CSRF API도 `200` 응답을 확인했다.

2026-10-02에는 로그인 화면 리다이렉트에서 `:8443`이 빠지는 문제를 수정했다. Nginx가 Host 헤더의 외부 포트를 보존하도록 바꾸고, Spring Security에 대시보드용 로그인 진입점을 명시했다. 비로그인 상태의 `/api/dashboard/index.html` 요청이 `302`를 반환하고 `Location`이 `https://localhost:8443/api/dashboard/login.html`임을 확인했다. 백엔드 빌드 및 `egov-backend`, `nginx` 재생성도 완료했다.

로그아웃은 fetch 리다이렉트 문제를 피하도록 서버가 `204 No Content`를 반환하게 수정해 빌드·반영했다. 다만 이 최신 수정 이후 실제 브라우저에서 로그아웃 버튼, 세션 무효화, 로그인 화면 복귀까지 다시 누르는 검증은 남아 있다. 배포 직후 첫 HTTP 요청은 백엔드 기동 중 `502`였으며 잠시 후 재요청에서 기대한 `302`를 받았다. 최종 전체 운영 검증으로 표시하지 않는다.

재난정보 외부 API 연동과 Android 캐시 즉시 무효화는 별도 미완료 항목이다. TAGO 버스노선정보 API는 2026-10-02 활용 승인 후 `.env` 서버 키로 확인하여 장성군 `cityCode=36450`, 총 105개 노선목록의 HTTP 200 응답을 확인했다. 실제 장성군 운행 노선·차량번호와 위치 응답을 대조하는 일, 서버 collector 구현은 남아 있으므로 실시간 연동 완료로 간주하지 않는다. 전체 구축 진행현황과 우선순위는 [전체 구축 진행현황](00_SmartBIS_구축_진행현황.md), 상세 테스트는 [egov-backend 변경 이력](SmartBIS_egov-backend_Build_Log_v1.0_updated.md)을 참조한다.

## 2026-10-02 as-built 보충

이 문서의 확정 디자인 및 운영 합의는 구현 완료 표시가 아니다. 2026-10-02 현재 앱 소스는 `MainActivity`의 시험용 `VideoView`/`ImageView` 레이아웃이며 24인치 전체화면 템플릿, 포스터+텍스트 복합 배치, 다중 이미지 카드뉴스, 반투명 하단 영상 제목은 아직 구현되지 않았다. 현재 `contents` 타입 제약은 `VIDEO`/`IMAGE`/`CARD`이고 manifest는 항목별 단일 `target_file_name`이다. 따라서 지자체와 정한 여섯 화면 형식을 표현할 최종 JSON 및 DB 계약도 확정·반영이 끝나지 않았다.

2026-10-02 watcher 오류 적재를 실제 PostgreSQL과 통합 시험했다. 의도적인 JSON 오류가 batch `FAILED` 및 error `OPEN`으로 저장되고, 같은 배치 ID의 재처리 성공 뒤 batch `PROCESSED` 및 error `RESOLVED`로 바뀌는 것을 확인했다. 시험 행과 배치 폴더는 제거했다. 이어 관리자 로그인 후 대시보드 HTML과 오류 요약/목록 API의 HTTP 200을 확인했고, 목록 0건은 시험 행 삭제와 일치했다. 실제 오류 행이 브라우저 표에 렌더링되는 것은 별도 확인 전이므로 화면 연계 완료로 단정하지 않는다.

2026-10-02 지역 표출 구현을 보완했다. arrival 예측에 다음 정류소 ID를 기록하고, 100m 이내의 다음 정류소 지역을 `target_regions`와 비교해 차량별 후보를 제한한다. 같은 정류소의 arrival가 연속 API 요청을 독점하지 않도록 한 번 표출 후 다음 우선순위로 진행시키며, 다음 정류소가 바뀌면 다시 arrival를 우선한다. 합성 DB 시험에서 지역 차량은 arrival 후 지역 전용 콘텐츠를, 위치/지역 없는 차량은 전역 콘텐츠를 선택했다. 시험 자료를 제거하고 새 백엔드를 배포했으며 HTTPS health가 UP인 것을 확인했다. 실제 TAGO 정류소·지역 데이터로는 검증되지 않았다.

## 2026-10-05 대시보드 MVC 및 게시 관리 화면 보완

- 대시보드 화면은 `static/dashboard/index.html`, 스타일은 `static/dashboard/css/dashboard.css`, API/상태 모델은 `static/dashboard/js/dashboard-model.js`, DOM 렌더링은 `dashboard-view.js`, 사용자 이벤트와 화면 흐름은 `dashboard-controller.js`로 분리했다. 프레임워크·번들러 없이 브라우저 ES module을 사용해 Spring Boot 정적 리소스 경로에서 직접 제공한다.
- 데이터 관리 화면에 게시 중·중지·게시 제외·전체 콘텐츠 건수를 추가했다. 서버에서 전체 상태 목록을 읽고 선택한 상태와 검색어로 화면 목록을 필터링하므로 상태 요약과 필터 결과가 서로 혼동되지 않는다.
- 좌측 메뉴형 운영 구조, 관리자 식별/로그아웃, 콘텐츠 상세, 중지·재개·논리적 게시 제외, 표출 정책 조회·저장, 수집 상태 및 TAGO 동기화 동작을 기존 API 계약에 맞춰 유지했다. 게시 제외는 파일/DB 원본 삭제가 아니라 게시 상태 변경이다.
- 스타일은 좁은 화면에서 메뉴와 게시 요약이 재배치되도록 보완하고 키보드 포커스 및 `prefers-reduced-motion`을 반영했다. CSS와 JS는 서버 제공 상대 경로로 불러오며 외부 CDN 의존성은 추가하지 않았다.
- 검증: 브라우저 JS 모듈 3개의 `node --check` 통과. 백엔드 Maven 패키징 및 실제 브라우저 화면/상태변경 검증은 이 변경에 대해 아직 수행하지 않았다. 따라서 서버에 반영된 완료 상태로 간주하지 않는다.
