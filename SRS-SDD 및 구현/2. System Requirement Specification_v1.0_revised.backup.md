# System Requirement Specification v1.3

## 1. 목적과 범위

SmartBIS는 차량용 Android 클라이언트가 정류소 도착정보와 승인된 콘텐츠를 표출하도록 하는 서버·클라이언트 시스템이다.

일반 사용자 대상 브라우저 서비스, 외부 Tomcat, 별도 WAS, /sht_webapp/는 범위에서 제외한다.

단, 운영자와 유지보수자가 서버 상태와 표출 상태를 확인하기 위한 내부 운영 대시보드는 범위에 포함한다. 운영 대시보드는 일반 사용자와 Android 클라이언트에 공개하지 않는다.

## 2. 시스템 구성

Android Client
  HTTPS 8443
  Nginx
  Spring Boot Embedded WAS
  PostgreSQL, Node watcher, TAGO collector, Disaster collector

내부 운영자
  운영망 또는 유지보수 PC
  운영 대시보드 API 및 화면

## 3. 콘텐츠 수신과 검증

Node watcher는 upload-store/YYYY-MM-DD/BATCH_ID를 수신한다.

검증 성공 데이터만 운영 표출용 contents 테이블에 적재한다. 검증 실패 데이터는 폐기하지 않고 원본 JSON, 미디어, 배치 정보와 오류 이력을 보존한다.

검증 실패 배치는 upload-store/error/YYYY-MM-DD/BATCH_ID로 이동한다.

검증 상태:

RECEIVED, VALIDATING, VALID, QUARANTINED, WAITING_PROVIDER, RETRY_REQUESTED, RESOLVED, CANCELLED

## 4. 오류 확인과 재처리

검증 실패는 메일 서버에 의존하지 않는다. 다음 수단으로 확인한다.

- content_ingest_batches와 content_validation_errors 저장
- Node watcher 시작 및 04:00 처리 후 미처리 오류 로그
- 오류 조회 API
- 내부 운영 대시보드
- 유지보수 체크리스트

오류 조회 API:

GET /api/v1/ops/ingest-errors
GET /api/v1/ops/ingest-errors?status=OPEN

제공측 확인 후 수정 재전송 또는 재처리를 수행한다. 원본은 운영자 승인 없이 자동 삭제하지 않는다.

## 5. TAGO와 100m 판정

서버는 TAGO 버스정류소정보 API로 정류소, 버스노선정보 API로 노선과 경유 정류소 순서, 버스위치정보 API로 노선별 차량 위치를 수집한다.

버스위치정보 API는 cityCode와 routeId로 호출하고 응답 vehicleno를 관리 차량번호와 대조한다. 응답 GPS와 다음 정류소 좌표를 서버에서 비교하여 100m 이내 여부를 계산한다.

Android GPS는 사용하지 않는다.

## 6. 재난문자

행정안전부 긴급재난문자는 이용신청 전까지 외부 API를 호출하지 않는다. 신청 전에는 DB 샘플로 지역 매칭, 활성기간, 우선순위, Android 전달을 검증한다.

## 7. 표출 우선순위

기본 순위:

관리자 강제 표출
> 정류소 도착정보
> 재난정보
> 지역 제한 콘텐츠
> 행사·공지

서버가 명시한 우선순위는 기본 순위보다 우선한다.

## 8. Android 요구사항

Android는 https://10.0.2.2:8443을 통해 서버 API를 호출한다. TAGO 및 재난문자 서비스키는 APK에 포함하지 않는다.

Android는 서버가 계산한 표출 결과를 조회하고, 미디어는 임시 파일에 저장한 뒤 완료 후 원자적으로 확정한다. 네트워크 단절 시 Room 캐시를 사용한다.

화면은 1920x1080 전체 화면을 사용하고, 노약자 가시성을 위해 큰 글자와 높은 명암 대비를 적용한다.

## 9. 내부 운영 대시보드

### SR-DASHBOARD-01 운영 현황

운영자는 대시보드에서 다음을 확인할 수 있어야 한다.

- 서버, DB, Nginx, Node watcher 상태
- 현재 등록 차량과 노선
- 차량별 현재 정류소와 다음 정류소
- 100m 도착정보 판정 상태
- TAGO 마지막 수집 시각
- TAGO 수집 성공·실패 상태
- 활성 재난문자
- 승인 대기 콘텐츠
- 승인 완료 콘텐츠
- 현재 표출 콘텐츠
- 지역별 표출 콘텐츠
- Android 마지막 동기화 시각
- 미디어 다운로드 실패
- 검증 실패 배치
- 제공측 확인 대기 오류

### SR-DASHBOARD-02 콘텐츠 운영

대시보드는 콘텐츠의 다음 상태를 조회해야 한다.

DRAFT, SUBMITTED, APPROVED, REJECTED, ACTIVE, EXPIRED

운영자는 승인된 콘텐츠의 표출 시작·종료, 대상 지역, 우선순위, 반복 간격, 최소 표출시간, 강제 표출 여부를 확인할 수 있어야 한다.

### SR-DASHBOARD-03 오류 확인

대시보드는 미처리 검증 오류를 표시해야 한다.

- 배치 ID
- 콘텐츠 ID
- 오류 코드
- 오류 메시지
- 수신 시각
- 재처리 횟수
- 제공측 확인 상태
- 원본 보관 위치

### SR-DASHBOARD-04 운영 API

초기에는 화면보다 API를 먼저 구현한다.

GET /api/v1/ops/summary
GET /api/v1/ops/ingest-errors
GET /api/v1/ops/disasters
GET /api/v1/ops/vehicles
GET /api/v1/ops/display-status
GET /api/v1/ops/contents/pending

### SR-DASHBOARD-05 접근 제한

운영 대시보드는 Android API와 분리한다.

- 운영자 인증 필요
- 일반 외부 공개 금지
- 역할별 권한 관리
- 승인·표출 변경 이력 기록
- 서비스키와 DB 비밀번호 화면 노출 금지

# System Requirement Specification v1.4 Dashboard Amendment

## 오류 대시보드 기본 표시

운영 대시보드는 별도 조회 동작 없이 접속하면 최근 3일 동안 발생한 검증 오류를 자동으로 표시해야 한다.

기본 표시 기준:

- 현재 시각 기준 최근 3일
- 최신 오류 우선 정렬
- 미처리 오류 우선 강조
- 전체 오류 건수 표시
- 미처리 오류 건수 표시
- 재처리 대기 건수 표시
- 처리 완료 건수 표시

기본 조회 SQL 기준:

```sql
WHERE created_at >= CURRENT_TIMESTAMP - INTERVAL '3 days'
ORDER BY created_at DESC
```

## 오류 전체 검색

운영자는 오류 조회 화면에서 전체 보관 데이터의 오류를 검색할 수 있어야 한다.

검색 조건:

- 시작일
- 종료일
- 처리 상태
- batch_id
- content_id
- error_code
- 오류 메시지 키워드

기본 조회 기간은 최근 3일이다. 운영자가 기간을 지정하면 지정한 기간 전체를 조회한다.

API:

```text
GET /api/v1/ops/ingest-errors
GET /api/v1/ops/ingest-errors?from=2026-09-23&to=2026-09-26&status=OPEN&keyword=template
```

응답은 조회 기간, 전체 건수, 미처리 건수, 항목 목록을 포함한다.

```json
{
  "from": "2026-09-23T00:00:00+09:00",
  "to": "2026-09-26T23:59:59+09:00",
  "totalCount": 5,
  "openCount": 2,
  "items": [
    {
      "batchId": "BATCH_20260926_0001",
      "contentId": "CNT_001",
      "errorCode": "MISSING_REQUIRED_FIELD",
      "errorMessage": "template 필드가 없습니다.",
      "status": "OPEN",
      "createdAt": "2026-09-26T15:20:00+09:00"
    }
  ]
}
```

## 오류 상세

오류 항목 선택 시 다음 정보를 표시한다.

- 배치 ID
- 콘텐츠 ID
- 오류 코드
- 오류 메시지
- 원본 보관 위치
- 최초 발생 시각
- 재처리 횟수
- 최근 재처리 시각
- 현재 처리 상태
- 제공측 확인 메모

## 운영 결정

메일 서버와 자동 메일 알림은 현재 범위에서 제외한다.

대시보드가 최근 3일 오류를 자동 표시하고, 기간·상태·식별자·오류 내용으로 전체 이력을 검색하므로 별도 메일 서버 없이도 운영자가 오류를 확인할 수 있다.
